## What This Project Is

**Quotagate** is a **local OpenAI-compatible proxy server** that turns a developer's existing
consumer AI _subscriptions_ (Claude Pro/Max, Gemini Advanced, ChatGPT Plus) into a programmatic API
endpoint — by driving the provider **CLI coding agents** (Claude Code, Gemini CLI, Codex CLI) that
are already authenticated against those subscriptions.

```
Developer App (OpenAI SDK) → localhost:8080 → Quotagate Proxy → Claude Code / Gemini CLI / Codex CLI → provider backend
```

The developer's app speaks the OpenAI SDK protocol and never knows it is talking to a CLI agent.
Quotagate translates OpenAI requests into CLI-agent invocations (primarily via a custom
`quotagate_complete` MCP tool) and translates the responses back into OpenAI-format responses.

**Core value proposition:** _You already pay for Claude/Gemini/ChatGPT — Quotagate makes that
subscription your API key._ Zero per-token API cost during development and testing; multi-provider
behind one endpoint; drop-in OpenAI SDK compatibility; no credentials leave the developer's machine.

**The full brief is `docs/schematics/quotagate-spec.md` — read it before making architectural
decisions.** This file is the _working_ knowledge base; the spec is the _product/architecture_
source of truth. A future marketplace (selling unused subscription quota) is documented in spec §7
but is **explicitly out of scope** — do not implement it.

> ⚠️ **Two different files are both named `CLAUDE.md` — do not confuse them.**
>
> - **`.claude/CLAUDE.md`** (this file) — the _project knowledge base_ for working on Quotagate.
> - **`~/.quotagate/CLAUDE.md`** — a _runtime artifact_ Quotagate writes/installs to constrain the
>   Claude Code agent at inference time (spec §3.6). It is generated by `src/mcp/claudeMd.ts`, never
>   hand-edited, and is a product output — not project documentation.

## Technical Stack & Commands

- **Runtime**: Node.js 20+ (LTS), TypeScript 5.x (`strict` mode, ESM).
- **HTTP server**: Fastify (low overhead, first-class SSE for Phase-3 streaming).
- **MCP**: `@modelcontextprotocol/sdk` — same ecosystem as the CLIs we proxy.
- **Validation**: Zod — OpenAI request parsing **and** `quotagate_complete` JSON-response validation.
- **Testing**: Vitest (TS-native, fast).
- **Lint/format**: ESLint + Prettier. Type-check via `tsc --noEmit`.
- **Build/bundle**: tsup (ships the `quotagate` CLI binary).
- **Package manager**: npm (the same channel users already have for the CLIs we wrap).

## Key Coding Conventions

### Engineering Integrity (MANDATORY)

- **This is a product, not a prototype.** Every implementation decision — from transport choice to error shape to test coverage — must be made with genuine intent for long-term reliability. Shortcuts are last resorts that require explicit justification and a documented plan to remove them. "It works in my smoke test" is not a quality bar.
- **No cheap fixes.** When a bug or mismatch is found, diagnose the root cause and fix it at the correct layer. Do not paper over structural problems with flags, callbacks, or fallbacks that hide the real failure. A workaround that makes a test pass without fixing the underlying contract is worse than a failing test — it erodes trust silently.
- **Intent matters.** If a fix feels like a workaround, it probably is. Before committing, ask: _is this the right fix, or the easiest fix?_ If the answer is "easiest," stop and escalate to the architect for a proper diagnosis. The cost of a workaround compounds; the cost of doing it right once does not.
- **Tests must prove the fix, not hide the failure.** A test that passes because it bypasses the broken code path (e.g., mocking the subprocess to return valid JSON when the real subprocess path is broken) is a deferred bug, not a passing test. Tests must exercise the production path they claim to cover.
- **The green gate is a ratchet, not a target.** Once `npm test` · `typecheck` · `lint` · `format` is green, it stays green. A task that breaks an existing passing test has regressed — full stop. Do not comment out tests, loosen assertions, or widen `any` suppressions to make the gate pass. If the test was wrong, fix the test and document why; if the code was wrong, fix the code.
- **The OpenAI response contract is the output invariant.** Any response that is "close enough but not quite right" is a breaking change for every consumer using the real OpenAI SDK. Validate the outgoing response shape in tests just as you validate the incoming request. Approximations are not acceptable.
- **Subprocess-phase code must survive the MCP upgrade.** Phase 1 ships subprocess-first (D-SEQ-01); Phase 2 replaces the transport with MCP. Every abstraction written in Phase 1 must be honest to the `CLIAdapter` interface contract — not to the subprocess implementation detail. If `adapter.complete()` leaks subprocess assumptions into `proxy.ts` or `argumentBuilder.ts`, it will break when the MCP adapter replaces it.

### Spec is the source of truth

- `docs/schematics/quotagate-spec.md` defines the architecture. Decisions marked **DECIDED** (spec §3.1, §3.2) and
  the **Invariants** (spec §8) are binding — do not revert them without documenting justification in
  the spec _and_ the decision log here.
- When the spec and this file disagree on architecture, the spec wins; reconcile by updating this file.

### TypeScript style

- `strict: true`. No `any` without a written reason. Prefer `unknown` + Zod narrowing at boundaries.
- ESM only (`"type": "module"`). Explicit file extensions in relative imports where required.
- Imports grouped: node builtins → third-party → local (`@/…` or relative).
- Async-first. All adapter/transport I/O is `async`; never block the event loop.

### Error handling

- All custom errors subclass a single `QuotagateError` base, defined in **`src/errors.ts`** only —
  never scattered into subsystem files (prevents import cycles, mirrors AlterEgo's exception policy).
- Boundary errors map to OpenAI-shaped error responses (`proxy.ts`), never raw stack traces to the caller.
- A failed transport falls back per the adapter contract; a fully-failed request returns HTTP 500
  with a descriptive (non-leaking) error (spec §4.4).

### Validation at the seams

- Parse the incoming OpenAI request with Zod in `proxy.ts`. Parse the `quotagate_complete` JSON output
  with Zod in `validator.ts`. Trust nothing from the model un-validated.

### The non-negotiable invariants (spec §8 — summarized; the spec is authoritative)

1. **The proxy never executes tool calls** — it returns declarations; the caller executes.
2. **No API keys from the developer** — the CLI tools own auth; Quotagate never stores credentials.
3. **Stateless per request** — caller sends full history each request; proxy stores nothing.
4. **Every adapter implements the same interface** — adding a provider = one file in `adapters/`.
5. **OpenAI response format is the output contract** — indistinguishable from the real API.
6. **MCP is primary transport, subprocess is fallback** — never subprocess-only in production.
7. **`quotagate_complete` tool definition is the primary constraint** — prompt-engineering is the net.
8. **Browser automation & session-token extraction are permanently excluded.**
9. **CLAUDE.md writes to `~/.quotagate/`** — never directly mutate `~/.claude/` or equivalents.
10. **Persist the process, never the conversation** — each `quotagate_complete` call runs in a fresh
    context seeded only by its args; `adapter.complete()` is a pure function of its inputs.
11. **One request in flight per MCP session** — serialize over each session; shard a pool to scale;
    never interleave concurrent requests on one session.

## Agent Roles & Workflows

Two sub-agent roles separate **design/review** from **implementation**. Use them for planning, code
review, troubleshooting, and atomic implementation.

### 1. Principal Architect (`principal-architect`)

- **Scope**: System architecture, the proxy/adapter/MCP design, data-flow contracts, config schemas,
  and the spec itself. The guardian of the spec's DECIDED choices and invariants, and of
  anti-overengineering discipline (no premature streaming, sharding, or marketplace work).
- **Responsibilities**:
  - **Planning** — authors phase plans, workstream specs, and elevates task stubs to
    implementation-ready (locks Decisions, Success Criteria, Assumptions-to-test, Test Strategy).
  - **Troubleshooting** — diagnoses transport failures, MCP/subprocess mismatches, validator/retry
    bugs; writes the diagnosis into the active tracker. Proposes fixes; **does not write code.**
  - **Review** — reviews implementation against the task tracker; verdict + findings; checks sign-off.

### 2. Backend Systems Engineer (`backend-systems-engineer`)

- **Scope**: Implementation of the proxy server, adapters (MCP client + subprocess), the
  `quotagate_complete` MCP tool server, CLI, subprocess/process-lifecycle handling, and tests.
- **Responsibilities**:
  - **Implementation** — writes the TS, the Vitest suites, and the integration/contamination tests.
  - **Tracking** — creates and maintains `docs/active/TASK_*.md` trackers during implementation,
    filling the Subtask Progress Table; does **not** write Review Notes / Sign-off.

### Troubleshooting handoff (PA → BSE)

1. **Diagnosis** — on a failing command/bug, `principal-architect` is invoked first; it pinpoints the
   failure mechanism and records it in the active tracker.
2. **Proposal** — PA proposes a fix with trade-offs and risks; does **not** write code.
3. **Approval** — the user reviews and approves.
4. **Execution** — `backend-systems-engineer` implements the fix and writes verification tests.

> **Spawn agents only when the work warrants it / the user asks.** Routine single-file edits, reads,
> and small changes are handled inline. The roles above are for substantial design and implementation
> units (a workstream, a hard diagnosis, a non-trivial task).

## Decision Log Protocol

Defines what a **decision** is, so the Session State "decisions" slots and the `PreCompact` archival
rule share a precise referent.

### What counts as a decision

A **decision** is a _deliberate, durable choice between alternatives that constrains future work_ and
would otherwise be re-litigated or forgotten. It is logged because the _reasoning_ — not just the
outcome — must survive into later sessions. Examples here: "MCP-primary transport, `--print`
fallback"; "persist the process, never the conversation"; "Node/TypeScript over Python"; "serialize
one request per MCP session".

**Not decisions** (do not log): routine implementation details visible in code/git; transient TODOs;
test counts; status updates; anything derivable by reading the repo. If it only matters to the
current task and leaves no constraint behind, it is not a decision.

### A decision has two states

- **Open** — still needs the user's input before work can proceed. Lives under **Open decisions for
  user** in Session State, stating the question, the options/trade-offs, and what is blocked.
- **Resolved (settled)** — made and not expected to reopen. Recorded as a **dated block** capturing
  **the choice, the rationale, and the rejected alternative(s)**. Settled only once locked and
  implemented or explicitly accepted — never while still under discussion.

### Lifecycle and archival

1. A decision is born **Open**, becomes **Resolved** once locked.
2. Session State keeps at most **2** dated Resolved-decision blocks inline (the `PreCompact` rule).
   Older blocks are **moved** (not copied) to `docs/archive/decisions.md`, appended chronologically,
   each retaining its date, choice, and rationale.
3. Archival is an explicit, tool-running step (`/house-keeping` or a session-end pass) — **never**
   inside compaction itself. A `PreCompact` hook can only inject reminder text; it cannot edit files.
